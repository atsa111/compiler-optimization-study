\section{Постановка задачи}

Работа посвящена сравнению оптимизаций компиляторов языка C для задач, характерных для системного и встраиваемого программирования. В качестве основного сценария рассматривалось программное обеспечение для встраиваемых и промышленных контроллеров, где одновременно важны быстродействие, компактность машинного кода и предсказуемость работы программы.

\textbf{Целью работы является} исследование влияния стандартных уровней оптимизации различных компиляторов на ассемблерный код, размер исполняемых файлов и время выполнения программ.

Для достижения цели были выбраны три компилятора: GCC 13.3.0 как основной, Clang 18.1.3 и Tiny C Compiler 0.9.27 как дополнительные. Исследование проводилось в Linux Mint 22.2 на архитектуре x86-64.

\section{Описание предлагаемого решения}

Основной эксперимент проводился на программе \texttt{optbench.c}, предназначенной для демонстрации различных видов оптимизаций компилятора. Для GCC и Clang исследовались уровни \texttt{-O0}, \texttt{-O1}, \texttt{-O2}, \texttt{-O3} и \texttt{-Os}. Для получения ассемблерного кода использовался флаг \texttt{-S}, а для анализа исполняемых файлов --- утилиты \texttt{size} и \texttt{objdump}.

Для оценки производительности использовалась программа \texttt{hyperfine}, позволяющая выполнять серию повторных запусков и получать среднее время выполнения и стандартное отклонение.

Кроме основной программы были разработаны четыре теста, характерные для выбранного сценария:
\begin{itemize}
    \item \texttt{bitmask} --- работа с битовыми масками и регистрами;
    \item \texttt{ring\_buffer} --- кольцевой буфер для обработки потоковых данных;
    \item \texttt{crc32} --- вычисление контрольной суммы;
    \item \texttt{low\_pass\_filter} --- простой цифровой фильтр.
\end{itemize}

Все исходные коды, скрипты сборки и результаты экспериментов размещены в репозитории проекта.

\section{Эксперименты}

В основной программе \texttt{optbench.c} оптимизация по размеру уменьшила секцию \texttt{.text} GCC с 3760 байт при \texttt{-O0} до 3021 байта при \texttt{-Os}. Для Clang размер уменьшился с 3492 до 3029 байт.

Дополнительные тесты показали, что результат зависит от характера вычислений. В тесте \texttt{bitmask} Clang с \texttt{-O2} показал среднее время $5.6 \pm 0.6$ мс, тогда как GCC с \texttt{-O2} --- $17.4 \pm 0.3$ мс.

В тесте \texttt{ring\_buffer} лучший результат показал GCC с \texttt{-O2}: $4.5 \pm 0.8$ мс. Clang с тем же уровнем оптимизации показал $5.9 \pm 1.3$ мс.

Наиболее заметная разница наблюдалась в тесте CRC32. Clang сократил среднее время выполнения с $210.0 \pm 8.9$ мс при \texttt{-O0} до $32.3 \pm 0.7$ мс при \texttt{-O2}. При этом размер секции \texttt{.text} увеличился с 1689 до 1756 байт. Таким образом, компилятор увеличил объём машинного кода ради существенного повышения производительности.

GCC в тесте CRC32 уменьшил время с $77.9 \pm 2.2$ мс до $64.3 \pm 0.7$ мс. В режиме \texttt{-Os} время составило $64.7 \pm 1.3$ мс, а размерсекции \texttt{.text} уменьшился до 1705 байт.

В тесте фильтра низких частот GCC с \texttt{-O2} уменьшил время с $10.9 \pm 0.9$ мс до $5.2 \pm 0.3$ мс.

Анализ ассемблерного кода показал, что GCC и Clang выполняют встраивание небольших функций, уменьшают количество обращений к памяти, преобразуют циклы и активнее используют регистры процессора. Clang в некоторых тестах применяет более агрессивные преобразования. TCC генерирует код, значительно более близкий к исходной программе, а результаты при \texttt{-O0} и \texttt{-O2} практически не отличаются.

\section{Заключение}

В ходе выполнения работы получены следующие результаты:

\begin{itemize}
    \item проведено сравнение GCC, Clang и TCC;
    \item исследовано влияние уровней оптимизации на размер и скорость программ;
    \item получен и проанализирован ассемблерный код;
    \item разработаны дополнительные тесты для сценария встраиваемых систем;
    \item выполнены повторяемые измерения производительности;
    \item подготовлены автоматические скрипты сборки и анализа;
    \item настроена автоматическая проверка проекта в GitHub Actions.
\end{itemize}

Полученные результаты показали, что невозможно выбрать один компилятор, который был бы лучшим во всех ситуациях. GCC показал стабильные результаты на разных типах нагрузки, Clang в отдельных тестах обеспечил более высокую производительность, а TCC оказался значительно менее агрессивным с точки зрения оптимизации.
